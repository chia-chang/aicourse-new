# 結果檢討

> 這是**挖空模板**。標 ★ 的地方要你自己填。
> 重點是「看到什麼現象 → 代表什麼問題 → 下一次怎麼改」，讓 AI 像店長一樣檢討。

## 什麼時候用

每跑完一次 `npm run simulate`，要決定下一版策略怎麼改時。

## 試算結果裡有哪些線索

試算工具每天會印出：客人數、收入、備貨、宣傳、報廢（清潔費）、淨利、任務、星等、資金，以及「沒買到的客人」：

| 線索 | 意思 |
|---|---|
| 賣完買不到 | 有人想買，但貨不夠 |
| 嫌太貴 | 價格超過客人剩下的預算 |
| 想吃的沒上架 | 客人想吃的菜今天沒賣 |
| 因為討厭的菜不進門 | 上架了某位客人討厭的菜 |

## 對症下藥表

| 看到的現象 | 代表的問題 | 下一次怎麼改 |
|---|---|---|
| 賣完買不到很多 | 備貨太少 | 那樣菜多備一些（注意合計不能超過 80 份） |
| 報廢 15 份以上 | 【規則書】報廢越多清潔費越高：6～15 份超過 5 份的部分每份 3 元，16 份以上另加 50 元；報廢份數＝備貨−賣出，備貨成本也白花了。【推測】備貨比實際想買的人多；也可能是客人討厭或嫌貴而沒進門。要看盤點確認，不能直接下結論。 | 先看倉庫盤點是哪幾樣報廢最多。有證據的才減備貨，備貨可往「賣出＋賣完後沒買到」靠攏。若同時看到「嫌太貴」，再考慮降價。注意總報廢要壓在 15 份以內，避免被收 50 元大型廚餘清運費。 |
| 嫌太貴很多 | 【規則書】客人只在價格 ≤ 剩下預算時才買，離開時說太貴，代表價格超過他的預算。【推測】定價偏高，或預算低的客人比例高。 | 先對「嫌太貴」集中的那樣菜降價，且降到可定價範圍內、並盡量不超過建議售價。要寫明降價會犧牲單份收益，並用下一版試算比較。一次只改最多 3 個地方。 |
| 想吃的沒上架很多 | 【規則書】客人想吃的菜沒有上架就買不到，會離開。【推測】上架組合沒有對上客人的需求；一天最多上架 4 樣，不能全上。 | 看客人話語找出被想買最多的菜，換進上架清單，換掉需求最少或沒人想買的那樣。換上架時要重新檢查合計份數 ≤ 80、備貨成本沒超過資金。 |
| 因為討厭的菜不進門 | 【規則書】客人討厭的菜只要有上架，他就不進門，也不留評價，等於白白少一位客人。【推測】上架了某一類客人討厭的菜（例如對某味道不喜歡的客人）。 | 找出是哪一位客人討厭哪樣菜，評估這樣菜帶來的銷量與被趕走的客人哪個多，再決定要不要下架。這是取捨，不一定要下架。 |
| 星等往下掉 | 【規則書】星等看進店客人中「滿意」與「不滿」的比例：不滿 ≥ 25% 或滿意 < 30% 會降 0.5 顆，不滿 ≥ 40% 或滿意 < 15% 會降 1 顆。「不滿」是什麼都沒買到。【推測】主因可能是沒買到（賣完、太貴、沒上架）；定價超過建議售價也會讓買到的人只算「普通」。 | 先分辨不滿的來源，是賣完、太貴還是沒上架，再對應調整：缺貨就補備貨、太貴就降價、沒上架就換菜。降低不滿比例，星等才會停止下滑；星等會影響隔天來客數，所以要優先處理。 |
| 我自己發現的現象：宣傳後增加來客，但淨利未改善 | 【觀察】花了宣傳費後來客數變多（規則書：200 元＋20%、500 元＋45%），但當日淨利沒有比不宣傳的版本好。【推測】新增收入可能抵不過宣傳費與新增成本；多出來的客人可能因為賣完、太貴、沒上架而什麼都沒買，反而變成「不滿」。這些都是待核對的推測。 | 先用數字核對，不要憑感覺：1. 新增收入＝宣傳後營業收入−對照版本營業收入。2. 新增成本＝宣傳費＋多備貨的成本＋多出的廚餘清潔費。3. 若新增收入 ≤ 新增成本，宣傳就是虧的。接著看新增來客的流向：變成買到的，還是「賣完買不到／嫌太貴／沒上架」。若多出的客人買不到，優先補備貨或調上架；否則先把宣傳費回到 0。每次只改一處，用試算比較。 |

## 步驟

1. 讀試算結果，逐天找出上表的現象
2. 每一個現象，照對症下藥表提出一個修改
3. **一次最多改 3 個地方**，這樣才知道是哪個修改有效
4. 把修改後的策略存成新的檔案（例如 `plans/v2.json`），不要覆蓋舊的，方便比較

## 回報格式

```text
1. 第 N 天：（現象）→（問題）

1. …
下一版檔名：
```
